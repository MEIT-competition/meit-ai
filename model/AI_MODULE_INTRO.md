# AI 모듈 소개 — 위험음 방향 인지 웨어러블

작성: 이주영 (인공지능 파트) · 팀 "팔방송이" · 2026 제5회 MEIT

## 이 모듈이 하는 일

웨어러블 허리띠의 마이크로 수집된 소리를 실시간으로 분류해서, 위험한 소리인지 아닌지·얼마나 위험한지를 판단합니다. 이 판단 결과(클래스 + 확신도)는 전자 파트의 방향 추정 결과와 합쳐져서, 최종적으로 어느 방향 진동모터를 얼마나 강하게 울릴지 결정하는 데 쓰입니다.

```
마이크 4채널 입력
   └→ [전자] 게이팅 주기마다 TDoA로 방향 추정, 해당 구간을 분류 대상으로 전달
        └→ [AI, 이 모듈] YAMNet 임베딩 추출 → 커스텀 분류층 → {클래스, 확신도}
             └→ [AI, 이예은] 위험도 판단 로직 → 진동 세기 결정 → 모터 구동
```

## 왜 이렇게 설계했는가

처음부터 오디오 분류 모델을 학습시키려면 수만 개 단위 데이터가 필요합니다. YAMNet은 이미 52만 개 이상의 오디오로 521개 소리를 구분하도록 사전학습돼 있어서, 그 지식을 그대로 가져와 위에 작은 분류층(Dense 512 → Dense 4)만 얹으면 적은 데이터로도 쓸만한 성능이 나옵니다. 실제로 학습되는 파라미터는 52만 개뿐이라 CPU로도 학습이 빠르고, 3주 안에 끝내야 하는 대회 일정에도 맞았습니다.

클래스는 horn(경적)·siren(사이렌)·crash(충돌음)·normal(일상소음) 4종입니다. 원래 예선 기획안엔 "돌발상황"이라는 클래스가 있었는데, 정의가 모호하다는 심사 피드백(#4)을 받아서 본선에서 crash(쾅 소리·급브레이크·유리 깨지는 소리)로 더 구체화했습니다.

이 시스템은 위험음을 놓치는 것(위음성)이 일반 소음을 위험음으로 오인하는 것(위양성)보다 훨씬 치명적이라, Recall(재현율)을 최우선으로 뒀습니다. 학습 손실 함수에서 danger 클래스에 더 큰 class_weight를 줬고, 임계값도 Recall 90% 이상을 만족하는 것들 중에서만 오탐이 가장 적은 지점을 고르도록 `threshold_search.py`에서 자동으로 찾게 했습니다.

확신도 보정(Calibration)도 넣었는데, 확신도 구간별로 진동 세기를 다르게 매핑하는 설계(예: 0.4~0.7 → 약하게, 0.7 이상 → 강하게)가 의미 있으려면 모델이 뱉는 확신도 수치가 실제 정확도와 얼추 맞아야 하기 때문입니다. 신경망은 보통 과신(overconfident)하는 경향이 있어서 Temperature scaling으로 보정하고, ECE(Expected Calibration Error)로 보정 전후를 비교합니다 (`calibration.py`).

노이즈 대응도 데이터 단계부터 고려했습니다. 심사 피드백에서 가장 많이 지적된 부분(#2, #5, #6)이 실사용 환경의 잡음 처리와 오탐 관리였어서요. 허리띠 하드웨어가 나와야 실제 모터 노이즈를 녹음할 수 있지만, 그 전에도 공개 데이터로 danger 클립에 normal 소리를 섞어 합성 잡음 데이터를 만드는 실험을 해봤습니다 (`augment_data.py` — 다만 SNR을 너무 세게 잡았더니 오히려 성능이 떨어져서 지금은 미적용, 자세한 건 TRAINING_REPORT.md 참고). 하드웨어가 나오면 실제 모터 on/off 쌍 녹음으로 교체·보강할 계획입니다.

## 데이터

| 클래스 | 공개 데이터셋 | 비고 |
|---|---|---|
| horn | UrbanSound8K, ESC-50 | |
| siren | UrbanSound8K, ESC-50, Kaggle Emergency Vehicle Siren Sounds | 라벨링 완료된 상태로 바로 사용 가능 |
| crash | ESC-50(glass_breaking), NINA Dataset | 공개 데이터가 가장 부족한 클래스, 자체 녹음 비중이 큼 |
| normal | UrbanSound8K 나머지 클래스 | 사람 말소리 등 보강 필요 |

모든 데이터는 16kHz mono, 4.5초 클립으로 통일하고, 원본 파일 단위로 train/val/test fold를 나눠서 같은 녹음이 여러 split에 걸쳐 들어가는 데이터 누수를 막았습니다.

## 평가 지표

Recall(재현율)이 핵심 지표고 목표는 90% 이상입니다. Precision/F1은 보조 지표로 보고, 시간당 오탐 횟수는 일상소음 상황에서 실제로 몇 번이나 잘못 울리는지를 보는 지표(심사 피드백 대응)입니다. 그 외에 확신도 보정 품질은 ECE로, 모터 노이즈로 인한 성능 저하는 off/on 쌍의 예측 변화율·확신도 하락폭으로 봅니다 (`motor_noise_eval.py`).
